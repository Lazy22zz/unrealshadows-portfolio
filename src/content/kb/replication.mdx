## 30 秒理解

```cpp
UPROPERTY(ReplicatedUsing = OnRep_Score)
int32 Score;

void AMyActor::GetLifetimeReplicatedProps(TArray<FLifetimeProperty>& Out) const
{
    Super::GetLifetimeReplicatedProps(Out);
    DOREPLIFETIME(AMyActor, Score);                                  // 无条件：服务器 → 所有客户端
    DOREPLIFETIME_CONDITION(AMyActor, Secret, COND_OwnerOnly);       // 只发给拥有者
}
```

- 只有服务器写入的值才会被复制；客户端改了也只是本地。
- `OnRep_` 只在**客户端**收到新值时调用，服务器本机不会调——服务器要自己调一次（或直接广播）。
- 一个 Actor 是否同步给某个客户端，先看 **relevancy**：`bAlwaysRelevant`、`bOnlyRelevantToOwner`、`bNetUseOwnerRelevancy`、`NetCullDistanceSquared`、隐藏且无碰撞时默认不同步。

## 解决什么问题

服务器是唯一的权威，客户端需要足够的信息去显示。复制解决“把状态送到客户端”，而 OnRep 解决“状态到了以后做什么”。难点在于：多个字段不保证一起到、两端的时钟不一样、表现不能拖慢网络。

## 在本项目中的应用

**规则一：要一起到的东西打包成一个结构体。** 胜利标志和胜者原来是两个复制字段，客户端可能先收到“胜利了”，胜利界面立刻弹出并锁定，之后才收到胜者——名字就永远丢了。现在是一个 `FUS_VictoryState`，胜者名字在服务器解析好一起发。集合进度、硬币锁、滑柜状态都是同样做法。

**规则二：截止时间用服务器时钟。** 服务器写 `GetTimeSeconds() + 8`，客户端拿自己的 `GetTimeSeconds()` 比较，会提前 1~3 秒（客户端世界时钟比服务器晚了加载时间）。读写两端都改用 `GameState->GetServerWorldTimeSeconds()`。

**规则三：复制状态，不复制运动。** 滑柜只复制“目标停位、阶段、起点参数、服务器时刻”，两端用同一个函数按服务器时间算出当前位置，所以一次转动只发几个包，载人漂移 0 cm。

## 常见错误

- 期望 OnRep 在服务器上也触发。
- 两个相关字段分开复制，UI 在中间状态里“定格”。
- 绝对时间戳用本地时钟比较。
- 复制指针指向一个**本身不复制**的关卡 Actor（比如 TargetPoint）：本项目改为复制下标，两端从关卡数据里查表。
- 同值写入也去广播，导致客户端重复播放效果——本项目的 setter 普遍“同值早退”。
